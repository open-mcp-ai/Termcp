MULTI-HOST

多机编组：一个 TermCP，管住所有机器

横向扩展不需要部署：多开一个终端窗口，就多一台机器进控制面。

1

在本机跑一个 TermCP 实例（npx -y @open-mcp-ai/termcp）。

2

开三个终端会话，分别 ssh user@node-1、node-2、node-3 —— 在控制台或直接让 AI 建都行。

3

AI 通过 MCP 同时向这三个终端写入命令：每个会话是一个 session_id，每个窗口是一个 shell_id，可以并行读写、也可以一个窗口一条命令。

4

想加机器？再开一个终端窗口。三台和三十台是同一套模型，只是多几个 session_start。

远程机器什么都不用装 —— 只要开了 SSH。密钥、跳板与密码都留在你本地那个 TermCP 里，目标主机上没有任何 TermCP 组件、也不会有它的进程。

SECURITY MODEL

凭据归 TermCP，不归 AI

Termcp 保管 SSH 登录所需的密码、私钥等认证信息。不会交给 AI，也不会泄漏。这些凭据只存在你本地那个 TermCP 实例上，远程主机对此一无所知。

凭据只存在本地实例

写进 ssh_config 的密码、私钥与口令只留在你运行 TermCP 的那台机器上，读接口只返回 profile 名，永不回读明文；远程主机上没有任何 TermCP 组件。

密码不进模型上下文

遇到 sudo 密码、MFA 或 [Y/n]，Termcp 把提示交回给人：你在浏览器里输入，它留在那条 shell 里。

审阅模式兜底

按会话开启的审批闸门：Agent 经 MCP 的每一次写入都等你接受或拒绝，才落到终端上。

本地与远程，一个控制面

本机 shell 零配置直接开；远程走 SSH，密码、私钥、ProxyJump 跳板链都由你本地的 TermCP 打理，目标主机不需要安装任何东西。Agent 面对的是同一套工具。

人机平等共驾

双方写同一条终端，每一屏都实时看得见。无缝接管、即时切换，告别黑盒盲操。

安装无依赖
