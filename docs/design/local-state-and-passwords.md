# Local state 与独立密码

状态：已实现，2026-11-02。此文取代旧设计中的“登录密码修改同时轮换 MK”和“密钥封装随主机正文存放”的运行时合同。

登录密码与配置加密密码是两份独立凭据，仅首次注册默认由同一次输入初始化。用户修改任一密码，不同步另一份，也不保存密码间的绑定关系。注册后弹窗说明这一点。

```text
登录密码 → Argon2id + 独立 salt → 登录校验记录

配置加密密码 → Argon2id + 配置 salt → MK
系统/ENV KEK → 解开 MK 的自动解锁封装 → 同一个 MK

MK → 解开各对象 EDK → 独立 DEK → 配置正文
```

没有新增密码 KEK 层。MK 仍直接由配置密码派生；macOS Keychain、Windows DPAPI、Linux Secret Service 或显式 ENV KEK 只提供并列的可选自动解锁路径。自动解锁不等于浏览器登录。两种密码校验使用独立 salt，登录哈希从不作为 MK/KEK。

## 存储和提交

同一 data-dir 由既有目录锁排他管理，当前存储如下：

```text
local-state/
  state.json
  objects/<catalog-or-auth-object-id>/<generation>.enc
ssh_configs/<host>/
  <generation>.enc   # encrypted host configuration stays in its host directory
```

`state.json` 使用私有文件权限和严格版本化 JSON，最多 16 MiB，是统一提交点。它包含 `keyring`（既有 KDF/verifier/provider 槽位）、`login`（账户公开身份、PHC 格式 Argon2id 校验记录及修订）、`heads`（catalog/auth 当前代际）、`envelopes`（各对象完整信封头，含独立 EDK）、`profile_identities`（对象与主机身份映射）、`profile_paths`（主机代际密文相对路径）及待清理旧文件清单。没有密码或 MK/DEK 明文。

主机配置正文保留在原主机目录的代际密文文件中，catalog/auth 正文使用 local-state/objects。正文对象保留信封 v1 的稳定数据头和密文，EDK/封装 nonce/Key ID 集中存入 state。读取时重建完整信封并沿用既有身份、用途、代际、长度、正文哈希及认证解密检查；分离存储不改变密码学 AAD 合同。单独复制正文文件不足以恢复，备份必须包含同一提交的 state 与对象。

保存先写入、同步新的不可变正文，最后原子发布 state 中的 EDK 和引用。更新失败不发布新引用，旧代际保持可读；认证验证完成后清理不可达代际。全局索引绑定对象身份、代际及主机目录中的相对路径。主机身份写入加密 catalog，并在全局状态中索引；已有非秘密 identity 标记和关联文件保持兼容。加密不移动原主机目录，主机改名时目录整体改名，密文字节及身份不变；删除后同名重建不继承旧身份。

## 登录与保险库状态

登录校验记录允许服务端在保险库锁定时读取，不通过 HTTP 返回。JWT 签名密钥和活跃浏览器会话仅存在本次运行内存，旧私有状态中的签名字段只保留格式兼容，不再用于签发会话。因此能够表达“已登录但保险库锁定”。

- `/auth/login` 校验独立登录密码。首次旧账号登录验证历史凭据后，原子建立独立校验记录。
- `/auth/unlock` 要求有效 Cookie、CSRF 与配置密码，恢复配置/身份/策略/凭据；可选重绑自动解锁。
- 已登录但数据不可用时，只允许账号、退出、改登录密码和解锁；业务入口及 MCP 返回 423。
- 系统自动解锁后仍需浏览器登录。退出浏览器只撤销该登录，不锁住其他 Agent 使用的保险库。
- 浏览器登录、配置解锁、真实 MK 重封各有独立生命周期。重封未完成也要求从解锁路径续跑。

## 修改密码和轮换

`POST /auth/password` 只替换登录校验记录、递增凭据修订并撤销浏览器会话；不更改 keyring、MK、EDK、主机正文或 MCP 凭据，保险库锁定时也可操作。

`POST /api/config-storage/password` 只处理配置密码。先发布新密码派生 MK 与受它保护的旧 MK，再一次性提交全局 EDK 重封表，全部校验后退役旧 MK。三次全局发布都支持中断恢复；正文文件保持原文件身份与原字节。已登录的浏览器不因此退出。缺失/不可用的自动解锁提供器仍保留密码恢复路径。

密码派生与 provider 工作继续释放普通业务互斥锁，提交前复核 keyring 快照。全局状态的修改序列化并保留其他分区的最新值，避免并发权限保存覆盖登录记录或相反。首次账户与登录校验记录一起发布，重复建立 bootstrap 被拒绝。

## 升级与异常

旧 `keys/config.keys`、`ssh_configs/store.enc` 和 `auth.enc` 先按原身份接入全局状态。各主机代际密文留在原主机目录，在 state 发布前保留完整旧信封，解锁验证后再原地分离封装头。曾被集中存放的主机正文在解锁验证后复制回对应主机目录，发布相对路径后才清理集中副本；已有主机路径缺失时不回退采用集中副本。密码模式可先保持锁定；解锁后验证 catalog、全部活动主机和认证对象，再尝试清理旧源。未完成清理保留清单供下次重试。旧 `auth.json` 在账户迁移成功后删除，不生成明文密码备份。

既有主机身份、加密对象身份、正文代际和权限引用保留。旧明文账户如原配置密码不同，分别证明两份旧凭据，不再强行统一；没有独立登录记录的历史加密账户，首次密码登录建立新校验记录。

状态损坏、缺失 state 但存在正文、缺失密钥或未记录的 catalog 丢失均不得当作新安装覆盖。已发布的新布局不回退读取旧目录；不支持用旧版本程序写入新布局。旧不可恢复备份、已泄露密钥和控制解锁进程的本地程序不在静态存储保护范围内。
