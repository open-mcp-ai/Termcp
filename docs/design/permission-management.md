# 权限管理：PC 页面与执行边界

状态：已实现，2026-10-29。用户确认：权限和 token 移入新页面，PC 优先，逐 Agent 鼠标选配功能与主机范围。本次确认取代早期“所有 Agent 只共用一份业务策略”的候选范围。

页面 `/permissions` 继承现有蓝色操作色和明暗主题，属于任务型管理界面。顶部保留工作区、权限管理、账号导航；左侧为 Agent 列表，右侧为当前身份的权限/Token 标签页。功能与主机选择并排，保存栏固定在配置区底部；顶部反馈不随内容滚走，错误同时写入相应操作旁。账号页 `/auth` 只保留账号、改密和退出。

新建 Agent 时发送 `issue_token:false` 和显式空策略。创建后选中该 Agent，勾选功能，选择全部/指定/无主机，保存后再签发 token。空功能和空选主机均不授权；不会为新的 UI 身份隐式授予全权。未保存的更改及尚未收起的首次 token 展示都有离开保护。旧 API 的默认创建并签发流程仍兼容；旧记录缺少 policy 时保留原有功能/all-host 权限并在页面明确显示。

功能分组为会话查看/管理、终端读/写、文件读/写、端口转发、外部协议、主机配置读/写、扩展、别名和通知。主机列表只返回名称与稳定身份，不返回连接秘密。主机改名不丢授权；删除后同名重建不继承旧身份。失效的选中身份在界面中保留为不可用项，可主动取消。全局主机配置写入和扩展管理仅允许全部主机范围；这类全局操作不能伪装成单主机权限。

Agent 策略与修订一起保存在既有认证密文。保存使用 Agent 修订做并发冲突检查。认证 context 带有服务端构建的动态策略读取器，每次操作读取当前权限，客户端不能提供或改写该读取器。策略修改取消该 Agent 的在途 token 请求；原 token 在新请求上读取新策略，无需重新签发。

工具入口在现有 admission 前检查功能与所有目标；DSL 在别名展开后的统一分发处检查，参数分支仍经实际工具能力检查。主机范围覆盖已有连接、通道、peer、任务和本地文件传输；文件复制检查两端。会话/主机/任务列表按范围过滤，`--all` 不扩大 Agent 视图。人端和管理员 MCP token 不套用 Agent 业务策略；资源 restriction、namespace 和部署约束继续生效。

当前支持允许/禁止，不实现委托审批。已有会话要求审核的 Agent 操作由 WebUI 人工执行，避免排队后权限收紧、旧审批仍执行的问题。已开始的后台任务与远端进程遵循原生命周期，保存权限不会承诺撤销已经发生的副作用。允许终端执行、协议访问或转发意味着可使用对应主机的系统/网络能力，不能理解为进程沙箱。
