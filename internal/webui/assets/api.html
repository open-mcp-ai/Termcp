1. MCP endpoints

SSE

Path /sse Claude --transport sse

Configure only /sse; JSON-RPC uses automatically.

Streamable HTTP

Path /stream Claude --transport http

Single MCP endpoint. Use this for Open WebUI and HTTP/Streamable HTTP clients.

Both transports expose the same tools. The most common connection bug is using /sse where the client expects /stream, or the reverse.

Authentication

When termcp starts with --auth-token / --auth-hash (or the matching environment variable), the same token protects Web UI, REST, MCP, and WebSocket. (Only the read-only documentation endpoint /api.md stays open without credentials so agents and scripts can fetch it before configuring a token.)

ClientHow to authenticate
API / MCP / scriptsAuthorization: Bearer <token>
BrowserA native 401 login prompt appears; username is ignored and the password is the token.
Browser WebSocketA successful Basic prompt sets an HttpOnly termcp_token cookie, which same-origin WebSocket handshakes send automatically.

Generate a salted hash with termcp --gen-auth-hash. Do not put tokens in URLs or copied client configuration. Use TLS through a reverse proxy when exposing Basic authentication beyond a trusted local network.

2. Agent docs (no MCP)

Documents (markdown)

One URI, two access paths: the same files are served over HTTP and published as MCP resources (resources/list). MCP tool arguments/results come from the tools/list schemas, so no separate tool reference is served.

DocumentURLWhen to use it
api.mdYou will drive termcp over HTTP yourself (REST/WebSocket): endpoints, bodies, output-cursor semantics.

No separate skill is served: the REST API is one endpoint, POST /api/term, carrying the same command language as the MCP term tool. An agent learns it from the instance itself with {"cmd":""} (guide) and {"cmd":"help"} (every directive), so there is no written tutorial to go stale.
